# 相机界面跟着屏幕旋转、图标不转（2026-11-12）

## 现象
OplusCamera 取景界面会随手机横过来整体旋转（系统自动旋转开着时），而原厂行为应是：
界面固定竖屏，只有变焦数字、模式按钮等图标随重力方向转动。

## 原因
1. **清单声明 `screenOrientation="behind"`**：在 HyperOS 上跟随下层窗口，系统会把
   相机 Activity 转成横屏。
2. **`Util.M0()`（"界面跟随系统旋转"）为真**：`pref_photo_preview_rotate_key` 默认
   `follow_system` 且系统自动旋转开启时，`Camera$o.onOrientationChanged` 请求
   `SCREEN_ORIENTATION_SENSOR`，相机不再自己转图标。
3. **选错了旋转策略**：`o6.a.a()` 按 `com.oplus.camera.support.activity.rotate` 选择
   `o6.g`（SensorActivityRotationDecision）或 `o6.c`（Portrait…，`l()` 恒为假）。
   原厂 SDK 默认值是 `"1"`，移植包上 `CameraConfig` 读成假，于是选了 `o6.c`，
   `Camera.E0` 永远不把角度下发给控件。
4. **进不了"强制竖屏"状态**：即使用 `o6.g`，`onOrientationChanged` 里调用
   `decision.i()` 前要过 `nb()` 与 `Util.A0` 检查，后者依赖 ColorOS 相册元数据和
   Oplus `FlexibleTaskView`，移植包上不成立，`l()` 仍为假。
5. **90°/270° 对调**：`E0` 的控件分支假设 Activity 本身已被系统转过，会把 90 与 270
   互换；界面固定竖屏后图标就会转反。

## 修复（Sense 1.51 / 模块 1.7.15 起）
`CameraOrientationHooks`，只作用于 `com.oplus.camera.Camera`：

- `CameraConfig.getConfigBooleanValue("com.oplus.camera.support.activity.rotate")` → `true`，
  恢复原厂默认，选用 `o6.g`；
- `Util.M0(Context)` 仅在 `Camera.E0` 内返回真（逐个转图标），其余场景返回假（界面不跟转）；
- `Camera.E0` 执行前若 `o6.g.l()` 为假则替它调用 `decision.i(activity)` 进入强制竖屏，
  并预先对调 90/270，让控件拿到真实传感器角度；
- `onCreate` 后请求竖屏；`setRequestedOrientation` 收到 UNSPECIFIED/USER/BEHIND/
  SENSOR/FULL_SENSOR/FULL_USER 时改为 PORTRAIT。

## 验证
系统自动旋转开启，手机横向左右各转一次：界面保持竖屏，变焦数字与按钮朝向正确，
照片方向正确（用户实测）。
