>

## 4. 构建可复现性

### 4.1 OS4.0.4.0（2026-11-17，当前）

用 `scripts/build_h40_userspace.sh` 构建 system / system_ext / product：

1. 解出 4.0.4.0 的 system、system_ext、product、mi_ext、mi_product，按 `build_haotian_h19_boot.sh` 的配方合并 mi_ext / pangu、删 Nfc_st 和 Updater、合并 mi_ext 属性。
2. system：TeleService XtsApp 三处补丁（`build_h19_signal_fix.sh` 的同一段 smali 补丁；4.0.4.0 的 `onHookDone` 结构与 0.19 相同）、RMX 原厂 MTP rc、XMNfcNci。
3. system_ext：`patch_miui_services_fp_stub.py` 重打 4.0.4.0 的 miui-services.jar，删除它的 odex/vdex/art 及 `oat/arm64/miui-services.*.fsv_meta`（与 0.19 包的文件集一致）；Settings 原厂版连同 oat 保留。
4. product：DPI 500、build.prop 追加块（NFC 5 项、刷新率 2 项、FOD 7 项）、haotian.xml 六处、亮度曲线、指纹特性 XML、三个相机权限 XML、OplusCamera 目录（APK 与 0.19 包逐字节相同），删 MiuiCamera。追加块和直接携带的文件取自上一版整包的实机回读（`REF_*` 参数）。
5. `mkfs.erofs -zlz4hc -b4096 -T0`，file_contexts 为三分区 contexts 拼接；raw 镜像入包。

核对结果：三个分区与 0.19 包共有的路径（system 4814、system_ext 3674、product 2360）SELinux 标签全部一致；product 的 build.prop 与 0.19 包相比，除版本号外只差一项 donor 自己删掉的 `persist.audio.laggy.detect.enable`，haotian.xml 与 0.19 包完全相同。

换底包时要连带检查模块叠加到系统分区的库：这次只有两个音频策略库变了（重新定位 8 处调用点，偏移不变，只是字符串地址平移），`libnativewindow.so` 等未变。Sense 引用的类名在 4.0.4.0 中全部存在（静态检查，方法签名没有逐一核对）。
