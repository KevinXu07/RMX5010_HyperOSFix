## 5. 明确不做/不适用

- **LTPO 模块**：用户确认系统已生效，不做。
- **OP13 IOplusVibrator / 800~2400 振幅 / 双马达 RTP**：RMX 是标准 `IVibrator` + qcom HV 单 LRA，硬件语义不同；用“私有 ID 映射 + VibrationScaler 系数”替代。
- **双马达专属 SRT 波形**：RMX 单马达，不适用。

## 6. 建议下一步

1. 完成第 1 节的用户/硬件验证（IFAA、LHDC、充电、音频、触感、采样率、抬起亮屏）。
2. 合并后优先做一轮全量 hooks 回归：MiCharge 电池页、IFAA processCmd、LHDC
   接口、双击/抬起亮屏、钱包刷卡页。
3. 功能优先级：§22/23 通知 → §24 核心破解 → §33/§44 稳定性 → §39/§40 游戏与调度。
4. 触感全套 RTP 先不做；根据实际手感决定是否值得为 RMX 重做波形。
5. §36/§37/§41/§42 属于体验增强，放后。
- **ColorOS 钱包系统 App 身份**：KSU system overlay 因 `/data` case-insensitive 不支持 overlayfs，未成功；当前为用户态安装。若发卡/风控要求系统身份，需要 loop ext4 overlay 或 system/system_ext EROFS 注入。
- **ColorOS 钱包账号/发卡/交易**：需用户登录并完成真实门禁/公交/银行卡测试；当前只证明 UI、默认钱包、WALLET 角色和 eSE C0 路由。
- **钱包 scope 会被卸载清掉**：卸载重装钱包包后必须重新写 scope 并重启，否则 FinShell 会显示“钱包不支持在该系统运行”。
