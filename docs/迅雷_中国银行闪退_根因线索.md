# 迅雷 / 中国银行闪退根因线索（2026-11-10）

## 现象

- 迅雷、中国银行（`com.chinamworld.bocmbci`）启动约 1 秒即退出，反复出现。
- `dumpsys activity exit-info` 显示 `reason=2 (SIGNALED)`、`status=9 (SIGKILL)`，即被信号杀死，不是 Java 崩溃。
- 用户反馈：第一版随刷机包打包的模块（1.5.7 一代）正常，后续版本开始闪退。

## 实机对照实验（RMX5010，模块 1.7.5 / versionCode 42）

| 条件 | 结果 |
|---|---|
| 现状（ZygiskNext + LSPosed + hma + keymint 全部启用） | 迅雷约 1s 被 SIGKILL |
| `zygiskd disable-zygisk true` + 重启 zygote | 迅雷正常启动并保持存活 |
| Zygisk 开启，`znmod disable zygisk_lsposed`（LSPosed 的 zygisk 模块）后重启 | 迅雷正常启动，到达隐私弹窗 |
| Zygisk 开启、LSPosed 启用 | 复现 SIGKILL |

结论：触发点是 **LSPosed 的 zygisk 库被注入每个应用进程**（即使该应用不在 LSPosed scope 内，`.so` 仍会加载）。加固/风控类应用检测到后由自身的守护子进程读 `/proc/<pid>/maps`、`/proc/<pid>/status`，再对主进程和自己发 SIGKILL。ZygiskNext 本体（不加载 lsposed 模块时）不足以触发。

## 为什么 scope 里没有这些应用也会被检测

LSPosed 是两层结构：

1. **Zygisk 注入层**：`zygisk_lsposed` 本身是一个 Zygisk 模块，Zygisk Next 会把 `zygisk/arm64-v8a.so` 和 `libzn_loader.so` 映射进**每一个从 zygote fork 出来的应用进程**，与该应用是否在 LSPosed scope 里无关。scope 不是“按应用挂载”，而是决定 LSPosed 拿到进程后**是否加载 Xposed 模块（Sense）并应用 hooks**。
2. **scope / hooks 层**：只有 scope 内的应用才会加载 `com.zephiel.sense` 并执行 hooks。

实机证据（2026-11-10，重启后）：

- 全设备有 17 个进程的 `/proc/<pid>/maps` 包含 `/data/adb/modules/zygisk_lsposed/zygisk/arm64-v8a.so`。
- 其中包括完全不在任何 scope 里的应用：`com.miui.home`（桌面）、`com.miui.weather2`、`com.android.quicksearchbox`、`com.miui.gallery`、`com.xiaomi.xmsf`、`com.omarea.vtools` 等。
- 也就是说，应用自检读 `/proc/self/maps` 时能直接看到 `zygisk_lsposed` 这个模块路径字符串（以及 `zygisksu` 的 `libzn_loader.so`），检测到的是 **LSPosed 的注入基础设施**，不是 Sense 的 hook。

因此“SukiSU 没有给这些应用挂载模块”也不影响：要让某个应用不被 Zygisk 注入，必须在 SukiSU 里给该应用打开 **UMOUNT**（即 Zygisk Next 的 denylist / per-app unount），LSPosed 的 scope 与这是两回事。

## 与版本差异的对应关系

- 1.5.7 一代刷机包没有内置 ZygiskNext/LSPosed，所以这些应用正常。
- 1.7.0（commit `6af5f3d` “feat(module): 1.7.0 安装时自动部署 ZygiskNext / LSPosed / Sense”）开始在安装时自动部署 ZygiskNext + LSPosed + Sense，LSPosed 从此存在于所有应用进程，用户升级后迅雷/银行开始闪退。
- Sense 依赖 LSPosed，不能简单关掉 Zygisk。

## 修复方向（未实现）

1. **按应用隐藏**：把迅雷、中国银行等风控应用加入 Zygisk Next 的 denylist（`enforce_denylist` 0=disabled / 1=enabled / 2=just_umount），使其进程不加载 zygisk，同时保留 Sense 所需 scope。设备上 SukiSU Ultra 的“超级用户”页有 UMOUNT 开关，Zygisk Next 的 denylist 列表疑似与 KSU 的 per-app umount 记录联动，需确认程序化写入方式（`/data/adb/ksu/.allowlist` 标志位或管理器 UI）。
2. **让 LSPosed/Sense 变成可选安装**：安装器里提供开关，不需要 Sense 的用户不装 Zygisk/LSPosed，从根上避免。
3. 修复后需回归：迅雷、中国银行冷启动；Sense camera 缩略图、钱包、触感等 hooks 不受影响。

## 已排除

- 模块本身（`rmx5010_fod_bridge`）的 mount/overlay：Zygisk 关闭时模块其余功能仍在，迅雷正常。
- hma_oss_zygisk、oh_my_keymint：实验时同时禁用后迅雷存活，但单独禁用 lsposed 即可存活，触发点主要是 lsposed。
