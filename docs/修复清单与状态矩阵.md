# 修复清单与状态矩阵

从 haotian OS4 时代到 nezha OS4 主线积累的全部修复。状态列含义：

- **✅ 实机** = 真机回归通过（注明验证深度）
- **⚠️ 条件** = 通过但有边界未覆盖
- **⏳ 离线** = 仅离线验证（哈希/标签/策略/差分），未刷机
- **❌ 否决** = 已验证不可行，勿重做

## C. 已否决（勿重做）

| 方案 | 结论 |
|---|---|
| cardapp trustlet 注入（从 haotian modem 提取） | QTEE `load_app` Error 12，TZ 信任链死路 |
| 从 RMX 原厂相机算法库修 P010 | 问题在框架层，不解决 |
| `dx.i.e()` → NONE | 小爱 s6 门槛失效 |
| 替换 MediaProvider APEX | 版本签名强依赖 |
| target `libandroidfw` 单独回填 | ABI 断裂 linker 崩 |
| TeleService 合法重签 | 破坏 shared UID/权限；只保留 signing block 预置 |
| 把 my_* 跳过大容量 product 直刷 | `Not enough space to resize partition` |
| 8elite 原包"全路径 `hal_allocator_default_exec`" | 卡第一屏（RMX 基线库有专用标签） |
| UI 字体缩放候选 / camera_save_v1/v2 / parser_targetlibs_v1 | 崩溃或无效，已删 |

## D. 未闭环（勿宣称修好）

- 状态栏反色特定场景（需复现路径）
- FCSN 离线定位（要锁屏密码）
- NFC 门卡 / 发卡（eSE/TEE 认证链）
- 相机白天发色 / 长焦 / 人像 / 录像长期回归
- 微信：能开欢迎页；聊天 / 登录未验
- `acc_udevid` 进程内自愈（当前靠 DB 直写 + 模块 worker 兜底）
- 音频哔声（nezha 版）：目标库为 system/lib64/libaudiopolicymanagerdefault.so（appname 5 处命中；本版无 impl 库），需定位函数后改 ret，尚未实施
- 账号闭包中 4 个辅助 HAL（mfidoca/mlipay/idmanager/mikeybag）无域、不启动

## E. nezha 主线的差异项（与 haotian 时代相比）

- `device_features/` 只有 `nezha.xml`，结构与 `haotian.xml` 不同 → DPI 修复需重适配（prop 改法仍适用）
- 硬件底换成全新 16.0.7.201 → **vbmeta flags 必须打 3**（haotian 时代的 OS3 成品本来就是 3，所以历史上没踩过）
- `init_boot_sukisu` 必须对**本版** `init_boot.img` 重新 patch
- A1/A3/A4/A5/A6/A6a/A7/A8/A9 等 haotian 时代载荷**不能直接复用**，需要按 nezha 重建（本仓库逐项跟进）
