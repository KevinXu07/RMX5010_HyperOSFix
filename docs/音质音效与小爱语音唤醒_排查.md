# 音质音效闪退与小爱语音唤醒：排查记录

日期：2026-11-16　机型：RMX5010　底座：原厂 vendor/odm 16.0.7.201 + haotian OS4.0.0.19

参考的是群里流传的两份方案（`移植修复方案/` 目录，txt + 文件）。那两份方案是给小米老机型 /
vndk30 机型写的，不少步骤在本机上不成立，下面记录实际结论。

## 1. 音质音效（com.miui.misound 16-4.0-4-20260903）

### 症状

打开即闪退：

```text
NullPointerException: ... String.equals(java.lang.Object) on a null object reference
  at h.i.M0(:17) <- h.i.N0 <- h.i.Y0 <- h.i.onCreatePreferences
```

同一时刻：

```text
AudioFlinger could not create effect ec7178ec-... / e069d9e0-8329-11df-9168-0002a5d5c51b, status: -2
HeadsetSettings: dirac initial failed
```

### 根因

`effect_selection` 下拉框只有在支持杜比（`ro.vendor.audio.dolby.dax.support`）或
小米音效（Dirac）时才会被 `setValue`。本机两者都没有，值一直是 null；`M0`、`onDestroy`、
`onPreferenceChange` 三处都直接对它调用 `equals`。

### 为什么不照搬方案

- 方案的 `libdirac.so` 是 legacy 音效库（导出 `AELI`）。本机音效 HAL 是 QTI AIDL
  `IFactory`（`/vendor/lib64/hw/libaudioeffecthal.qti.so`），只 dlsym
  `createEffect`/`queryEffect`/`destroyEffect`，legacy 库加载不了，加了 xml 也没用。
- 方案靠改 smali 回编 MiSound / miui-framework。Android 17 user 版会拒绝签名失效的预置
  APK（见 `Settings与overlay原厂化_SenseHook_20261102.md`）。
- 杜比需要底层 DAP，本机没有，强行让 `z.m.D()` 返回 true 只会显示一个不工作的杜比开关。

### 修复（Sense 1.55 / 48）

`MiSoundHooks.java`：在 `com.miui.misound` 进程 hook
`miuix.preference.DropDownPreference#getValue`，仅当 key 为 `effect_selection` 且结果为
null 时返回 `"none"`。这等价于应用自己算出的"无音效后端"状态：杜比 / 小米音效分类和图形
均衡器入口隐藏，其余页面正常。LSPosed 作用域新增 `com.miui.misound`（`register_sense_lsposed.sh`
已同步），需重启一次才生效。

小米音效、Dirac 均衡器、杜比在本机均无底层，不在本次范围。若以后要做，需要写一个 AIDL
效果库包装 legacy Dirac，工作量大且调音不是本机的。

## 2. 小爱语音唤醒（com.miui.voicetrigger 10.0.14.0-xiaomi）

状态（2026-11-16 00:56）：**未完成**。OPPO 小布 DSP 引擎在 HyperOS 上已验证可检测；
"小爱同学"走高通 PDK 的链路已打通到"模型加载、DSP 监听"，但第一级仍不触发。
测试工具源码：`tools/soundtrigger_probe/`（用法见其 README）。

### 2.1 本机唤醒硬件/软件现状（已确认）

| 项 | 结论 | 依据 |
|---|---|---|
| ST HAL | QTI soundtrigger3 AIDL（PAL），配置在 `/odm/etc/resourcemanager.xml` 的 `vui_platform_info` | `soundtrigger.qti.xml`，`STHAL`/`PAL` 日志 |
| 高通 PDK 第一级 | **存在**：`/vendor/dsp/adsp/stage1_pdk_module.so.1`（+ `_island` 版） | ADSP 动态模块目录 |
| 高通 GMM 第一级 | **不存在**；按 GMM 加载会 `Graph cfg ... failure:3`，引擎重置 `0x08001051` 返回 -95 | GMM 跑法日志 |
| ARM 第二级 | `libcapiv2svacnnvendor`（CNN）、`libcapiv2uvvendor`（声纹）、`udk7`、`rnn` | vendor/lib64 |
| OPPO 小布 | `BREENO_VOICE_UI`（vendor uuid `68ac2d41-e861-11e4-95ed-0002a5d5c51c`）+ `libcustomva_intf.so`，`module_type=CUSTOM1`（思必驰引擎），双麦 `va-mic-dmic-lpi` | ODM 配置 |
| 高通 LSM 服务 | `vendor.qti.hardware.ListenSoundModelAidl.IListenSoundModel/default` 已注册，跑在 audiohal 进程（`LsmServerWrapper`） | `service list` |
| 新版 VoiceTrigger | 只有 `LegacyWakeupSession`（直接读 `/odm/etc/XiaoAiTongXueMi.udm` 加载）+ 小米盘古/Permian 路径；**没有** `com.qualcomm.listen.ListenSoundModel`，不会合成模型 | smali |
| 旧版 VoiceTrigger（方案 v8.0.0.21-qcom） | 带完整高通 SVA 客户端；录入时 `ListenSoundModel.extend(uim, keyword, user, 5 段录音)` 生成个人 udm，自定义词用 `createUdkSm(...lat...)` | smali |

### 2.2 过程与结论

1. **方案里的旧版 APK 已被改过，v3 签名校验失败**（CHUNKED_SHA256 不匹配），不能作为预置应用
   安装（Android 17 user 版拒绝坏签名预置包）。下面的实验都没有安装它，只把它的 dex 当库加载。
2. **新版录入卡在"同意声纹后无反应"**：`VT_MixEnrollManager: The engine is not initialized`。
   `files/algorithm_library/voiceprint_engine_model.bin` 只在 `ro.vendor.audio.soundtrigger.pangaea`
   / `.permian` / 白名单机型 / 玄戒平台时才从 assets 拷贝（`h0.f.J -> I`）。手动拷入 assets 里的
   `voiceprint_engine_model.bin`、`xiaoai_wakeup_engine_model.bin`、`udk_wakeup_engine_model.bin`
   后录入成功（数据目录 `training_audio/xatx/enroll/training1..5.pcm`，16 kHz mono s16le）。
3. **ST HAL 不认小米 UUID**：`61696d69-30f2-11e6-b0ac-40a8f03d3f1b`（小爱同学）/ `…3f1d`（自定义）。
   需要在 `resourcemanager.xml` 里复制 QC_VOICE_UI 段改 UUID。
4. **方案的 `XiaoAiTongXueMi.udm` 是老格式**（文件头 `eai2`，SVA 2.x）：`GetSoundModelHeader_ failed,
   err 6`。加载失败返回 INTERNAL_ERROR 后，middleware 会杀掉音频 HAL，VoiceTrigger 又不断重试
   → **音频 HAL 约每 5 秒重启一次**（实测 21 次）。
5. **`XiaoAiTongXue.uim` 是本机能解析的新格式**（SML 头 `0x00180cc8`，关键词串
   `XATX.PDK6XS.PDK7_stage2.DNNUVv2`），子模型表在 0x1a8：

   | type | 版本 | 大小 | 说明 |
   |---|---|---|---|
   | 1 | 6.0 | 50 176 | 第一级，内部名 `PDK6_1st_stage` |
   | 32 | 6.0 | 53 248 | 第一级附属数据 |
   | 2 | 7.0 | 6 504 876 | 第二级关键词（CNN） |
   | 16 | 7.0 | 22 707 412 | 第二级声纹（DNN UV） |

6. **PAL 默认按 GMM 加载 type 1**（QC_VOICE_UI 段里 GMM 排在 PDK 前）→ 用 GMM 参数装 PDK 模型，
   DSP 不会检测。小米 UUID 段只保留 PDK 的 `first_stage_module_params` 后，PAL 日志
   `VUI module type:PDK`，加载/启动成功（只有一条无害的 `send non-persist cal failed 3`，
   小布跑法里也有）。
7. **用旧版 dex 合成个人模型成功**：`ExtendTest` 加载方案 APK 的 `com.qualcomm.listen.ListenSoundModel`
   → `query()` 取关键词 `XATX.PDK6XS.PDK7_stage2.DNNUVv2` → `extend(uim, keyword, "user1", 5,
   training1..5)`，`userMatch=92`，输出 29 262 944 B（子模型 type 1/2/4，第一级仍是 PDK6）。
8. **但 PDK 第一级始终不触发**。以下组合都没有 `event detected on SPF`，且说话期间 audiohal
   没有任何日志（说明不是第二级拒绝，是第一级没报）：
   - 原始 uim / 合成 udm × 单麦 `va-mic-mono-lpi` / 双麦 `va-mic-dmic-lpi`
   - 置信度 69 / 50 / 10；`recognitionModes` 1 与 3（带用户 1 的 ConfidenceLevel）
   - 真人说话与扬声器回放录音（回放会触发 `HandleDetectionStreamAction` 停-重配检测图，
     回放结果仅作参考）
9. **OPPO 小布引擎可检测（正对照）**：`OvmsTest` 用原厂 `my_product/etc/OVMS_1st_wakeup.bin`，
   经原厂 `OVoiceManagerService.apk` 自己的 `s3.d#j(byte[])` 打包（AISpeech 头），model uuid
   `7d5b82e9-e5c9-477e-afa4-60e68d30b462`、vendor uuid `68ac2d41-…`、关键词 `aispeech`、
   recognitionModes 3、置信度 69、RecognitionConfig.data = 4 字节 LE 声纹类型。
   原厂 `resourcemanager.xml` 无需改动。实测"小布小布"：
   - 置信度 69 / 声纹类型 0 / 模式 3：**触发**（`event detected on SPF`，回调 code=2）
   - 置信度 50 / 声纹类型 -1 / 模式 1：**触发**
   - 第一次的 69 / -1 / 3 未触发（原因未定，可能当时没说或说话时机不对）
   引擎重置 `0x08001051` 在 CUSTOM1 图上成功，进一步说明 GMM 图失败是 GMM 模块缺失。
10. **改用 TX 宏 `handset-mic` 做唤醒采集不行**：ACDB 没有对应 GKV（`acdb get tags from gkv
    failed with 19`），加载失败并触发一次 HAL 重启。
11. 新版 VoiceTrigger 的 flexkws（tflite）和声纹只是第二级：`MIXWVPWakeupSession` 在 DSP
    `onRecognition` 之后才开 AudioRecord 复核，没有独立常开的纯软件唤醒。

### 2.3 "小爱同学"还没验证的方向

- **完整复刻旧版的识别参数**：旧版 `LegacyWakeupSession` 对 `.uim` 用 1st/2nd 阶段分开的置信度
  （`get1stKeyphraseConfidenceLevel` / `get2ndKeyphraseConfidenceLevel` / `get2ndUserConfidenceLevel`），
  `.uim` 路径时 extra 置信度写 `0x3eb`，并可附带扩展 opaque data
  （`com.qualcomm.qti.sva.session.OpaqueDataHelper`）。目前测试只填了标准 phrase extra。
- **模型版本**：第一级是 PDK6，ADSP `stage1_pdk_module` 只有 `lib.ver.1.0.0`，看不出支持的模型版本。
  可试 `ListenSoundModel.createUdkSm`（用 `merged_language_model.lat` 按文字合成，可能生成新版
  第一级），或 `checkModelCompatibility` / `getSMLVersion` 查兼容性。
- **DSP 侧日志**：需要 ADSP 诊断日志才能看第一级是否在跑、得分多少。

### 2.4 备选："小布小布"桥接（已验证可行，未实现）

在 VoiceTrigger 进程（有 `MANAGE_SOUND_TRIGGER`，语音唤醒打开时常驻）里用 Sense hook：
把 `LegacyWakeupSession` 的模型/UUID/参数换成 OVMS 那套（模型数据可预先打包，约 117 KB），
检测后跳过 VoiceTrigger 的第二级（flexkws/声纹只认"小爱同学"），走它原本的唤醒成功流程拉起小爱。
唤醒词只能是"小布小布"（DSP 上的思必驰模型固定，无法训练成"小爱同学"）。
加载失败时不能快速重试，否则会复现音频 HAL 循环重启。

### 2.6 注意事项

- **overlay 到 /odm/etc**：overlay 根目录继承 upperdir 的 SELinux 标签。upper 在 `/data/local/tmp`
  时是 `shell_data_file`，音频 HAL 进不了 `/odm/etc`，回落到 `/vendor/etc/acdbdata/sun_mtp`
  并 `gsl_init failed -114`。必须先 `chcon u:object_r:vendor_configs_file:s0` upperdir。
  已挂载的 overlay 因 HAL 占用常 `umount` 失败，用 `umount -l`。
- **改 resourcemanager.xml 后需重启 audiohal**（`kill $(pidof audiohalservice.qti)`），声音会断一下。
- **加载失败 = HAL 重启**：任何返回 INTERNAL_ERROR 的 `loadPhraseModel` 都会让 middleware 杀 HAL。
  做实验时先停用 VoiceTrigger（`pm disable-user --user 0 com.miui.voicetrigger`），避免它自动重试。
- **日志缓冲**：本机日志量大，默认缓冲几秒就被覆盖，调试 ST 前先 `logcat -G 16M`。
- **DexClassLoader**：Android 14+ 要求被加载的 apk/dex 只读（`chmod 444`），目录要 shell 可写。
