# 抬起亮屏：严格服从系统开关（RMX5010）

状态（2026-10-26）：

- Settings 已暴露系统“抬起亮屏”开关（`support_gesture_wakeup` /
  `isSupportPickupWakeup`）。
- SystemUI 只读取 `pick_up_gesture_wakeup_mode`，**不再写回**该设置。
- 新增 `ContentObserver`，设置变化立即注册/注销 type 22
  `pick_up_motion`，不需要等 SystemUI 重启。
- 实机：开关打开时注册成功，关闭时注销成功。

## 1. 原问题

旧移植为了保证首次适配，会在 `KeyguardSensorInjector` 构造后直接把
`Settings.System.pick_up_gesture_wakeup_mode` 写成 1；同时
`updatePickupSensorRegistration()` 不读取该设置。结果是：

- 用户关闭“抬起亮屏”后，传感器仍然注册；
- SystemUI 进程重建/重启后，设置又被写回开启；
- 系统设置页可能根本不显示这个开关，因为 HyperOS 的能力标志没有声明。

## 2. 实现

### 2.1 Settings（暴露开关，不强制开启）

`SettingsHooks`：

```text
FeatureFlagHooks.forceTrue(loader, Set.of("support_gesture_wakeup"), "settings")
hook com.android.settings.AodAndLockScreenSettings.isSupportPickupWakeup() -> true
```

只声明能力，不写 `pick_up_gesture_wakeup_mode`。

### 2.2 SystemUI（只读开关）

`SystemUiHooks.hookPickupSensor`：

```text
pickupEnabled = Settings.System.getIntForUser(pick_up_gesture_wakeup_mode, 0)
shouldRegister = pickupEnabled
        && (!interactive || (keyguardShowing && wokeByPickup))
```

- 不再写设置；
- 运行时注册/注销 type 22 `pick_up_motion`；
- `ContentObserver` 监听 `Settings.System.getUriFor(pick_up_gesture_wakeup_mode)`，
  变化时调用 `updatePickupSensorRegistration()`；
- SystemUI 进程重建后仍是“设置说了算”。

## 3. 实测

开机时设置不存在（等价 0）：

```text
pickup sensor registered=false switch=false interactive=false keyguard=false
```

打开开关（息屏）：

```text
pickup sensor registered=true switch=true interactive=false keyguard=true wokeByPickup=false
```

关闭开关后，`dumpsys sensorservice` 中该监听记录被移除（计数 6 → 5），
设置保持 0，不再被模块写回。

日志还包含：

```text
pickup setting observer registered
pickup registration hooks=1
pickup sensor fixed: pick_up_motion  Wakeup, wakeUp=true
Settings pickup capability hooks=1 in com.android.settings.AodAndLockScreenSettings
```

## 4. Sense 应用的冲突

Sense（`com.zephiel.sense` / “感知”）有一个**独立的**
`LiftToWakeManager`：它自己注册加速度计、判断平放/抬起，并用
`PowerManager.SCREEN_BRIGHT_WAKE_LOCK` 唤醒屏幕。它不读取
`pick_up_gesture_wakeup_mode`。

因此如果同时启用：

- 系统开关关闭，但 Sense 的独立抬起亮屏仍可唤醒；
- 这就不符合“严格服从系统开关”。

建议二选一：

1. 让 Sense 的 `LiftToWakeManager` 先读取系统设置，关闭时不注册；
2. 或者停用 Sense 的独立抬起亮屏，完全使用系统的 type 22 传感器。

本次模块只保证系统开关路径严格；Sense 侧需要在接入时同步修改。

## 5. 使用与回退

```bash
# 系统开关路径
adb shell settings put system pick_up_gesture_wakeup_mode 1   # 开
adb shell settings put system pick_up_gesture_wakeup_mode 0   # 关
```

回退：从 LSPosed scope 移除 `com.android.settings` 只影响开关的显示；
移除 `com.android.systemui` 会恢复原 SystemUI 行为。模块不修改系统 APK。
