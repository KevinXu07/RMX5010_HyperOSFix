## 1. 我们在做什么

把 **OplusCamera 6.070.45**（ColorOS/realme 相机）系统级移植到 **RMX5010（realme GT7 Pro）**
的 haotian 4.0.0.19.XOBCNXM ROM 上。本机底层是**小米 CamX/CHI HAL**
（`vendor.camera-provider-service_64`），外加 Oplus ODM 层 `/odm/lib64/hw/camera.oemlayer.so`。
两者并不完全兼容，所以需要两层补丁：

- **KSU 模块 `rmx5010_fod_bridge`（当前 1.6.7）**：负责挂载/overlay、注入 ODM 库、
  替换 `/odm/etc/camera/config/camera_unit_config`、挂 R 角/灵动岛 overlay。
- **Sense Xposed 模块（`com.zephiel.sense`，包名 `local.mio.gt7profodfix`）**：在
  `com.oplus.camera` 进程里做运行时 hook，修 APK/SDK 与 ROM 不匹配导致的行为。

长期目标：相机全功能可用（拍照、变焦、长焦、录像、相册）。
当前正在攻的是**拍照**：预览和快门已经通了，剩下**长焦（2x）**和**应用自身保存**。

## 3. 关键约束（务必遵守）

- **不要卸载 KSU 模块 1.6.7**：否则 `/product/priv-app/OplusCamera` 会回落到坏的
  89f02709 APK，相机会崩。
- 打过补丁的 OplusCamera APK **无签名**，只能通过 PMS 缓存安装：必须保持
  **大小 193,164,793、mtime 0**；改大小/mtime 或清缓存后需要按
  **1.6.6 → 重启 → 1.6.7 → 重启** 重新播种。
- 不要走 6.020 preview6 stub 路线（1.6.3/1.6.4/1.6.5，201,922,949 B APK），缺类。
- `port_sources/`（readback_images 9 GB、stock201 12 GB）**不许删**。
- 测试完**立即锁屏**，防烧屏；R 角/灵动岛 overlay 由 1.6.7 的 `post-fs-data.sh` 挂载，别弄坏。
- 相机 App 的 dump 在 `E:/code/modify/_camera_apk`：`unitsdk_dump.txt`（unit SDK jar）、
  `classes12_dump.txt` / `p12`（APK dex）。找类/方法用 dexdump 文本搜索。

## 5. 建议的下一条路

1. **先把 2x 切长焦黑屏当主问题**（预览都起不来，变焦/长焦成片都无从谈起）。
   - 抓 2x 切换瞬间的完整 logcat（相机 + HAL + `CAM_ERR` + APS）。
   - 对照 1x 正常时的 session stream 列表（`BaseMode.buildStreamSurface` 日志），
     看 2x 是否换了 usecase / 掉了 `preview` 流 / 触发 SAT 切换时序问题。
   - 文档 D44 里记录过“普通模式切长焦偶发黑屏”，当时结论是 APS/实况照片路径在 SAT 切换
     瞬间拿不到 `OplusCaptureResult` 丢帧，属间歇时序；先确认这次是不是同一现象。
2. **长焦成片**：若预览能通，再试从 `sat_photo_case` 去掉 `raw16_output rear_tele` 与
   `capture_raw10_dol rear_tele`，让长焦走直接 YUV（参考之前对 `rear_wide` 的处理），
   看 `role 3` 是否不再是噪声。
3. **卡顿**：量化——`dumpsys gfxinfo com.oplus.camera`、Choreographer skipped frames、
   HAL frame 间隔；确认是预览重渲染 hook 太重，还是 APS miss frame 重试导致。
   可疑点：`CameraPreviewFixHooks` 每帧 `requestRender`、全局
   `ImageReader.acquireNextImage` hook（拍照保底用）。
4. 相册桥接（App 自身保存）留到拍照稳定之后。
