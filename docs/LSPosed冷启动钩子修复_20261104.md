# LSPosed 冷启动钩子修复（2026-11-04）

## 1. 现象

用户反馈：打字和其他所有振动都"没有之前那种感觉了"。振动配置（`op13_fix_haptic_scale`）和
KSU 模块都没问题，问题在 **Sense 的 system_server 钩子根本没装**。

## 2. 根因

- `zygisk_lsposed` 只带 `service.sh`，`lspd` 在 init 的 **services** 阶段启动；
- zygote 在更早的 **zygote-start** 阶段就已经 fork 出 system_server；
- system_server 里的 LSPosed SystemServer 桥**只连一次**，连不上就永久放弃。

于是每次冷启动：应用进程（相机、设置、SystemUI）的 Sense 钩子照常加载，
但 system_server 里没有 `SystemServerHooks`，小米私有振动 effect ID（72–217、401–410、
10001）没有被翻译成 RMX 支持的 0–12，框架直接判 `IGNORED_UNSUPPORTED`。

证据：

```
# 冷启动的 verbose log 里只有
LSPSystemServerService: starting new bridge
# 之后没有任何 (system) 记录；bridge 建立时刻 01:36:50.844，zygote 启动 01:36:50.239
# 手工 setprop ctl.restart zygote 后立刻出现
(system) ... system_server hooks installed
(system) ... haptic compatibility active: map=1 info=1 scale=1 click=1 strength=2
```

为什么"以前是好的"：钩子只有在 lspd 已经在跑的时候才会装上，也就是装/更新 LSPosed、
改模块、或手工重启框架之后的那一次。之后手机一直没冷启动，就一直正常。
不是新加的步骤，是每次冷启动都在悄悄丢。

## 3. 修复

在 `kernel-src/ksu-module/service.sh`（KSU 模块 `rmx5010_fod_bridge`）末尾加了一段
LSPosed 冷启动兜底，**不再单独装 `zz_lspd_early` 模块**：

1. 等 `lspd` 就绪（同一 services 阶段，顺序不保证，最多 60 秒）；
2. `lspctl status` 确认至少有一个启用模块，否则跳过；
3. 等 `system_server` 起来，再给 3 秒（实测钩子日志在 fork 后 1 秒内出现）；
4. 最新 `modules_*.log` 里有 `system_server hooks installed` 就结束；
5. 没有的话，**在开机动画期间**重启一次 zygote（`/dev/.lspd_early_zygote_restarted`
   保证每次开机最多一次）；
6. 60 秒后写一行自检结果到日志，不再重启第二次。

### 时间线（2026-11-04 10:54 实测）

| 事件 | uptime | 说明 |
|---|---|---|
| 第一套框架 `boot_progress_start` | 6.586 s | |
| 兜底重启 zygote | **12 s** | `early_start.log` 带 uptime 记录 |
| 第二套框架 `boot_progress_start` | 12.958 s | |
| `boot_progress_enable_screen` | 22.694 s | 只有第二套到达 |

第一版把判断放在 `boot_completed + 30 秒`，实测 uptime 16.6 秒才重启，而第一套框架
16.0 秒就 `enable_screen`，有概率闪一下屏。改成"框架起来后 3 秒"判断后，重启点提前到
uptime 12 秒，稳定落在开机动画内，用户看不到黑屏，只是动画多放约 7 秒。

### 日志

- `/data/adb/lspd/log/early_start.log`：每次开机的判断与结果
- `adb logcat -t LSPD_EARLY`：重启动作

## 4. 试过并放弃的方案

不要重复尝试：

1. **post-fs-data 提前启动 lspd**（配合给 `zygisk_lsposed/service.sh` 加 `pidof lspd`
   跳过）。桥确实能提前 4 秒建好，但这样启动的 lspd 会以
   `Fatal signal 11 (SIGSEGV) fault addr 0x314 / Instruction Abort, pc=0x314` 崩溃，
   而且之后每次手动启动也照样崩，必须
   `su -c '/data/adb/ksud module install /sdcard/LSPosed-v2.2.1-7912-release.zip'` 重装模块
   才能恢复。两次崩溃（01:01、01:39）都发生在手工改过
   `/data/adb/modules/zygisk_lsposed/` 目录之后，**不要再改那个目录**。
2. 直接改 `zygisk_lsposed/service.sh`：单独改不会崩，但没有解决顺序问题，已还原为原厂 136 B。

## 5. 与一加13 修复模块的对比

`os4/external/OP13HyperOSFix` 的 `haptics/HookEntry.java` 走的是同一套 system_server
钩子（`VibratorManagerService.getVibratorInfo` 扩 supportedEffects、
`PrebakedSegment.getEffectId` 做 ID 映射），映射表与 Sense 基本一致。

区别只在于它**没有兜底**：文档明确写"模块不包含 `service.sh`、`post-fs-data.sh`"，
原生组件靠 system_server 在 `PhoneWindowManager.systemReady()` 后 12 秒发静默广播拉起——
也就是说它假定每次开机钩子都在。它用的是 Vector（LSPosed 分支）+ 自己的 Zygisk，
时序和我们这台（LSPosed 2.2.1 + ZygiskNext 1.5.2）不同，所以没碰到这个竞态。
把它的模块放到我们这台机器上，一样会丢钩子。

## 6. 约束

- 不要卸载/停用 KSU 模块 `rmx5010_fod_bridge`（相机的 overlay 和库注入都在里面）。
- 不要手工改 `/data/adb/modules/zygisk_lsposed/` 里的文件；坏了用 `ksud module install` 重装。
- 开机后约 12 秒会重启一次 zygote（框架），这是正常的，屏幕停留在开机动画。
