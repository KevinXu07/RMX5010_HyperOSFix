# 相机滤镜预览黑屏：美摄引擎设备校验（2026-11-12）

## 现象
OplusCamera 右下角选任一滤镜（LUT 类，如 `jzk-movie.cube.rgb.bin`），预览变黑；
相机仍在工作，拍照能保存，但成片没有滤镜效果。

## 原因
预览滤镜走相机内的 IPU 滤镜单元 → 美摄（Meishe）引擎 `/odm/lib64/libmsnativefilter.so`
（JNI 包装层是 `libMsEffectSdk.so`）。`CNvComputeRenderer::Init` 创建渲染器前做设备校验：

1. `__system_property_get("ro.product.manufacturer")`；
2. 与静态构造函数写入的 `DEVICE_ARRAY` 逐一比较（两边都转小写）。名单以立即数编进代码，
   `strings` 搜不到：`OPPO`、`OnePlus`、`realme`、`motorola`；
3. 不在名单 → `Authentication is not allowed.` / `Create renderer failed!`，
   之后每帧 `effectSdkContext is null`，滤镜纹理全黑；拍照不经过这条路，所以能出图但无滤镜。

移植包把 `ro.product.manufacturer` 改成了 `Xiaomi`，所以必然失败。日志里
`NvInitNdkSymbols load error by function: ...` 是可选符号缺失，原厂 ColorOS 同样如此，无关。

## 修复（模块 1.7.14 起）
硬件本身就是 realme，只让滤镜引擎读到真实厂商，不改全局身份：

- `camera/odm/lib64/libmsnativefilter.so`：把字符串 `ro.product.manufacturer`（文件偏移
  0x632dd，.rodata 偏移等于虚拟地址）改为等长的 `ro.product.camera_maker`，共 8 字节；
  名单与代码均未改动。原版 sha256 `45f09b4a…`，补丁版 `c228a3d6…`。
- `camera_fix.sh`：post-fs-data 时 `resetprop -n ro.product.camera_maker realme`
  （已有值则不覆盖）。该属性落在 `default_prop`，策略有
  `allow coredomain default_prop read`，相机的 traceur_app 域可读。
- 补丁库随现有 `/odm/lib64` overlay（上层在 tmpfs `/data/local/tmp/rmx_camera`）挂载，
  标签 `same_process_hal_file`，与原文件一致。

注意：运行时测试不能从 `/data/adb` 直接 bind——KernelSU 会对普通应用卸掉来源在
`/data` 的挂载，相机进程仍看到原版；从 tmpfs bind 才生效。

## 验证
相机进程内库哈希为补丁版，日志 `Current device is realme`，无 Authentication 报错；
选滤镜后预览与成片均有滤镜效果（用户实测）。
