# 人脸录入卡在进度环：根因与修复（2026-10-26）

## 现象

HypserOS 4（haotian 0.19 用户空间 + RMX5010）录入人脸：HAL 实际已经录入成功
（`faceid` 已写入、`dumpsys biometric` 有人脸传感器、删除人脸能正常删），但
Settings 界面停在进度环，占比大约一半，永远不进入成功页；等多久都不动，只能返回。

## 证据链

实机日志（`logcat -b main,system,crash`，16M 缓冲）：

```text
00:53:23.863 D NewMultiFaceEnrollFragment: onEnrollmentProgress
00:53:23.863 D NewMultiFaceEnrollFragment: startFaceInputProgressAnimation
00:53:23.863 D NewMultiFaceEnrollFragment: mCurrentEnrollAnimationStep = 0, mFaceEnrollStep = 5, mFaceEnrollAnimating = false
00:53:25.278 D NewMultiFaceEnrollFragment: ... mFaceEnrollAnimating = true
00:53:25.709 D NewMultiFaceEnrollFragment: ... mFaceEnrollAnimating = true
00:53:26.600 D NewMultiFaceEnrollFragment: ... mFaceEnrollAnimating = true
[FACE_HAL][FaceSession]: onEnrollmentProgress(fid=..., rem=0)   ← 录入完成
```

整段日志里 **没有任何一条 `endFaceInputProgressAnimation`**（动画结束回调的日志）。

反编译 `Settings.apk`（classes3.dex）确认：

- `initProgressView()`：建立 `mFaceInputProgressViews` = circle_0..circle_4（FACE_INPUT_MULTI_STEP=5），
  0 号视图 `setAnimation("miui_face_input_progress_0")`，**没有** `addAnimatorListener`；
  循环只给 1..4 号视图 `addAnimatorListener(new $15(fragment))`。
- 全 dex 只有 `$15.onAnimationEnd` 会把 `mFaceEnrollAnimating` 置回 false。
- `startFaceInputProgressAnimation()` 首次播放 0 号视图并置 `mFaceEnrollAnimating = true`，
  后续调用都被 `if (!mFaceEnrollAnimating)` 挡掉。

结论：**0 号进度动画没有结束监听器 → 标志永远为 true → 状态机死锁在第一步**。
HAL、BiometricService、Settings 的收尾逻辑都正常，只是 UI 推进被卡死。

## 修复

给 0 号视图补挂同一个 `$15` 监听器。补丁位置（smali）：

```smali
invoke-direct {p0, v2}, ...$NewMultiFaceEnrollFragment;->generateViewUri(Ljava/lang/String;)I
move-result v2
invoke-virtual {v0, v2}, Lcom/airbnb/lottie/LottieAnimationView;->setAnimation(I)V
# ---- 新增 ----
new-instance v2, ...$NewMultiFaceEnrollFragment$15;
invoke-direct {v2, p0}, ...$15;-><init>(L...;)V
invoke-virtual {v0, v2}, Lcom/airbnb/lottie/LottieAnimationView;->addAnimatorListener(...)V
```

脚本：`scripts/patch_settings_face_enroll.py`（baksmali→改 smali→smali，替换 classes3.dex，
保留原签名块）。构建 system_ext：`scripts/build_system_ext_settings_patch.sh`
（同时删除 `priv-app/Settings/oat` 避免旧编译产物）。

已验证：补丁后 `addAnimatorListener` 从 1 处变 2 处、签名块 ID 不变、其它 zip 条目零差异；
`system_ext_facefix.img` 内 Settings.apk 标签 `u:object_r:system_file:s0`、哈希 `36f14220…`。
已刷入 `system_ext_a` 并开机，等待实机录入回归。

## 为什么官方机器不卡（推断）

官方布局/特性组合下 `FACE_INPUT_MULTI_STEP` 或 progress 视图集合与该代码路径不一致
（例如没有 circle_0 视图，首个分支直接走成功动画），因此这个监听器缺失不会暴露。
移植组合恰好命中「有 circle_0 + 走进度链路」这一分支。
